**1. Add section color tokens to globals.css**

Inside the existing `@theme` block, add section background tokens AFTER the existing color tokens:

```css
/* Section backgrounds — Light mode */
--color-section-hero: #FFF8F0;
--color-section-about: #1A1A2E;
--color-section-skills: #FF6B35;
--color-section-projects: #FF4444;
```

Inside the existing `.dark` block, add dark mode overrides:

```css
/* Section backgrounds — Dark mode */
--color-section-hero: #1A1A2E;
--color-section-about: #0F0F23;
--color-section-skills: #CC5528;
--color-section-projects: #CC3636;
--color-section-contact: #CCA832;
```

Also add section text color tokens for proper contrast (per CONTEXT.md decisions and RESEARCH.md WCAG findings):

Light mode:
```css
--color-section-hero-text: #1A1A2E;
--color-section-about-text: #FFF8F0;
--color-section-skills-text: #1A1A2E;
--color-section-projects-text: #FFFFFF;
--color-section-contact-text: #1A1A2E;
```

Dark mode:
```css
--color-section-hero-text: #F5F5F5;
--color-section-about-text: #F5F5F5;
--color-section-skills-text: #FFF8F0;
--color-section-projects-text: #FFFFFF;
--color-section-contact-text: #1A1A2E;
```

IMPORTANT: For skills text on orange bg, use charcoal (#1A1A2E) NOT cream — research found #FF6B35 on #FFF8F0 fails WCAG AA for body text. Charcoal on orange passes.

**2. Create Section.tsx component**

Create `src/components/Section.tsx` as a server component (NO "use client"). Props:

```tsx
interface SectionProps {
  id: string;
  colorToken: string; // e.g. "hero", "about", "skills", "projects", "contact"
  children: React.ReactNode;
  className?: string;
  fullHeight?: boolean; // defaults to true
}
```

Implementation:
- Outer `<section>` with `id`, `w-full`, background via inline style `backgroundColor: var(--color-section-{colorToken})`, text color via `color: var(--color-section-{colorToken}-text)`

- Support asymmetric layouts via optional 12-column grid: include a `grid` prop that when true adds `grid grid-cols-12 gap-6 lg:gap-12` to the inner container
- Add CSS `transition: background-color 0.3s ease, color 0.3s ease` for smooth dark mode transitions
- Export as named export: `export function Section`

Restructure layout.tsx to remove the max-w-4xl wrappers that prevent edge-to-edge sections.

**New structure:**

```tsx
<ThemeProvider>
  <Navigation />
  <main className="flex-1">
    {children}
  </main>
  <Footer />
  <Analytics />
</ThemeProvider>
```

Key changes:
1. REMOVE the outer `<div className="sticky top-0 z-50 ..."><div className="max-w-4xl ...">` wrapper around Navigation. Navigation will handle its own sticky positioning and container internally (Plan 02 handles the nav redesign, but this layout change is needed NOW so it stops constraining the nav).
2. REMOVE the `<div className="max-w-4xl mx-auto px-4 py-2 sm:py-8 ...">` wrapper around children and Footer. Replace with a simple `<main className="flex-1">{children}</main>`.
3. Move `<Footer />` out to be a direct child of ThemeProvider, after main. Footer will handle its own width constraints.
4. Keep the body className as-is (font variables, min-h-screen, bg, text, overflow-x-hidden).
5. The `<Navigation />` component is now a direct child of ThemeProvider — it will manage its own sticky behavior and backdrop-blur internally.

IMPORTANT: Do NOT change the font imports, metadata, or html tag. Only restructure the JSX inside `<body>`.

This change means:
- Homepage (page.tsx) can render edge-to-edge Section components
- Other pages (blog, notes, etc.) will need their own `max-w-4xl mx-auto px-6` wrapper inside their page components — but that is expected and handled in Phase 5. For now they will be full-width, which is acceptable as a temporary state.
